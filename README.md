# Vocal Map

歌詞に矢印、ブレス、強弱、発声方法、感情表現、自由メモを書き込み、自分専用の「歌唱設計図」を作るローカルファーストの練習アプリです。WebブラウザとiPhone/iOSで同じExpo/React Nativeコードを利用します。

## 実装済み機能

- 曲の作成、編集、削除（タイトル、アーティスト、曲メモ、複数行歌詞、空行保持）
- PCでは歌詞の語句を直接ドラッグし、iPhoneでは歌詞行をタップしてポップアップ内で先頭文字・末尾文字を選択した語句または行全体への記号追加
- 「文字の間（ブレス）」を選び、「君｜に」のような境界候補から位置を指定して、ブレスなどを歌詞と同じ高さの文字間へ配置
- 「背景色で歌い方を指定」で選択語句を色分け。裏声（ラベンダー）・ミックス（ミント）・地声（黄色）の候補に加えて、独自の名前と5色の背景色を指定できます。通常の記号やブレスとも併用できます。
- 同一語句の出現位置選択、文字範囲保存、重複範囲の拒否（記号を付けた語句に背景色は付けず、歌詞の読みやすさを維持）
- 語句対象の記号を歌詞の上に揃え、ブレスなどの文字間記号は歌詞と同じ高さに表示。記号の有無にかかわらず歌詞の基準線を統一
- 歌詞行の枠をなくしたシンプルな表示と、長い日本語歌詞の画面幅内での自動折り返し
- 36種類のプリセット記号、カテゴリ／お気に入り絞り込み
- テヌート、スタッカート、レガートを音楽記号で表示し、「伸ばす」「短く切る」など初心者向けの名前を併記
- クレッシェンド、デクレッシェンドを短い文字ではなくヘアピンの音楽記号で表示
- 曲線で上げる・下げる矢印（しゃくり／フォール）
- プリセットの編集と初期化、カスタム記号の作成・編集・削除
- 編集／練習を分けない統合画面（大きな歌詞、文字サイズ・行間調整、歌詞タップによる編集）
- 歌詞画面から履歴に依存せず曲一覧へ戻れる導線と、曲情報保存後の重複画面防止
- Web/iOS別の永続保存、JSONエクスポート／追加または置換インポート
- schemaVersion、インポート検証、データ移行（文字間配置は7、歌い方の背景色は8）
- 歌詞変更時の記号維持、対象語句および文字間の前後文脈による一意な再検索、再特定できない記号の要確認表示
- Safe Area、キーボード回避、44px以上の操作領域、狭い画面での折り返し、アクセシビリティラベル
- 曲作成・編集画面では入力欄だけをスクロールし、スマホでも保存ボタンを常に画面下へ表示

## デザインとナビゲーション

- コーラル、ミント、イエローを使った明るい配色。歌詞本文の背景は読みやすさを優先します。
- Webは「曲・記号・設定」を画面上部のロゴと同じエリアへ配置。スマホ幅でも上部にまとめ、操作のたびに画面下まで視線を移す必要がありません。
- iOS/ネイティブは下部タブを維持し、アイコンと大きめの文字・選択背景で区別します。
- 余白をコンパクトにし、PCでは曲・記号・設定カードを2列、狭い画面では1列にします。
- ナビゲーションのプラットフォーム差分は `components/navigation/AppTabs.web.tsx` と `AppTabs.tsx` に分離。保存やドメイン処理は共通です。

## 技術構成

- Expo SDK 57 / React Native 0.86 / React 19 / TypeScript
- Expo Router / React Native Web
- iOS・ネイティブ: `expo-sqlite/kv-store`
- Web: `localStorage`（`storage.web.ts`に隔離）
- ファイル入出力: Expo Document Picker / File System / Sharing。WebのファイルAPIは`dataTransfer.web.ts`に隔離
- Jest Expo / React Native Testing Library

UI、ドメイン処理、Repository、Storage Adapterを分離しています。将来はRepository実装を差し替えて、ログイン、クラウド同期、先生との共有、バックアップ、有料プランを追加できます。

## 起動方法

Node.js LTSと依存関係を準備します。

```bash
npm install
```

Web:

```bash
npm run web
```

iOSシミュレーター（macOS、Xcodeが必要）:

```bash
npm run ios
```

または`npm start`後に `w` でWeb、`i` でiOSを開けます。SDK 57対応のExpo Goまたは開発ビルドを使用してください。

## Web確認用URL

`main`ブランチへpushするとGitHub ActionsがWeb版をGitHub Pagesへ自動配信します。

- <https://tanbo-hiroooi.github.io/Vocal-Map/>

確認用URLのデータも外部サーバーへ送信されず、ブラウザ内に保存されます。localhostや別端末のデータとは共有されないため、端末ごとに曲を作成するかJSONバックアップをインポートしてください。

## 品質チェック

```bash
npm run typecheck
npm run lint
npm test -- --runInBand
```

単体テストは歌詞分割、空行、語句候補、文字間位置、絵文字を含む境界位置、歌詞変更後の再追跡、セグメント、重複、プリセット、インポート検証、移行を対象にしています。コンポーネントテストは曲一覧表示、曲保存、選択範囲を引き継いだ記号追加、文字間へのブレス追加・表示、記号付き歌詞の背景非着色、統合画面の歌詞タップ、カスタム記号作成を対象にしています。

## データとプライバシー

データはすべて端末内に保存されます。バックエンド、ログイン、外部API、広告、分析・追跡SDK、マイク権限はありません。歌詞の自動取得やスクレイピングも行いません。バックアップJSONには曲、歌詞、記号辞書、設定が含まれるため、利用者自身で安全に保管してください。

## MVPでの判断と制限

- 背景色の操作：PCは歌詞をドラッグ、iPhoneは行をタップして先頭・末尾の文字を選択 →「背景色で歌い方を指定」→ 歌い方と色を選択 →「この色分けを追加」。歌詞下に対象語句と歌い方の名前も表示します。変更する場合は同じポップアップ下部から対象の色分けを削除して付け直します。
- 名前と背景色は語句ごとに保存します。背景色同士は重複不可、背景色と記号は重複可です。歌詞編集で対象語句を一意に見つけられない場合は、着色を停止し「要確認」を表示します。旧データの語句が自動で着色されることはありません。
- 重なる語句範囲は表示の曖昧さを避けるため保存しません。
- 文字間の記号は複数登録できます。語句の上に付ける記号とは重複扱いになりません。
- 歌詞行編集では同じ位置の行を基準に記号を引き継ぎ、対象語句が一意に見つかった時だけ範囲を更新します。それ以外は警告付きの「要確認」にします。
- カスタム記号を削除後、既存Annotationはデータ保全のため残し、辞書参照がないことを「？」で表示します。
- 「～ なめらかに」はレガートと重複するためプリセットから削除しました。schemaVersion 4への移行時、未使用・未編集の旧記号は削除し、使用中または編集済みのものはカスタム記号として保持します。他のプリセットIDは変更しません。
- インポートの「追加」は同一IDを読み込んだ内容で更新します。設定は現在値を維持します。
- Android固有の最適化、クラウド同期、自動スクロール、画面スリープ防止、横画面専用UI、Dynamic Type連動は未実装です。
- iOSシミュレーターの画面操作確認と実機確認は、Xcode/端末のある開発環境で行う必要があります。
